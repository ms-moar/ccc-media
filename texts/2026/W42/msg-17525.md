# Все зависит от юзкейса. Можно и в ноушен настроить таск трек

**Дата**: 18.10.2026 14:10
**Топик**: Claude Code

Все зависит от юзкейса. Можно и в ноушен настроить таск трекинг, асанить комиты, PR И так далее.

Linear подойдет если работаете с командой над одним проектом, но все зависит насколько плотный поток тикетов и задач. Это из лучших командных таск трекеров.

Он написан на GraphQL через API можно кастомизириовать и сделать заполняемыми любые поля от инициативы до тикета.

Я написал свой таск трекер для харнесса, на Linear работал 2 года с командой и без + там нужна Pro подписка, чтобы вязать тикеты к комитам.

Аргументация к своему трекеру:
•  На linear один вызов шёл 1,8–2,3 с, а локальная база отвечает за 42–45 мс через CLI.

У меня весь контекст проекта в трекере - тикеты, комментарии к тикетам, комиты, PR, баги, заметки, напоминания для меня и для агентов, открытые вопросы, гриллинги, RFC (спеки). Все имеет связи.

Вообще появилось очень много разных трекеров, если нет особых требований, можно рассмотреть https://en.yougile.com/, но надо проверить API и лимиты по запросам.

Linear:

- 2 500 запросов в час и 3 млн очков сложности GraphQL в час на один API-ключ. Цифры записаны 2026-09-25 со страницы https://linear.app/developers/rate-limiting

###

Архитектура
Было:
• Агенты ходят в Linear по сети через CLI и GraphQL, из 83 файлов, без общего модуля.
• Сообщения шины лежат отдельно в SQLite.
• Связь тикета с картой кода — строки в теле тикета, которые ищут текстовым поиском.

Стало:
• Одна точка входа ticket_store.py к той же SQLite (режим WAL), где живут сообщения шины.
• Таблицы: ticket, link, event, label, comment.
• Тикет, решение, утверждение, карточка кода и кластер находок — строки одной таблицы с разным полем layer.
• Связи (blocks, parent-child, происхождение) — рёбра в link. «Заблокирован» — это запрос, а не статус.
• Каждая смена статуса пишется строкой event в той же транзакции.
• Захват тикета — один UPDATE с арендой на время.
• У каждого проекта свой ключ и счётчик (ACC-<n>, QNT-<n>…).
• Монитор сам переводит утверждение в Done по его команде проверки.
