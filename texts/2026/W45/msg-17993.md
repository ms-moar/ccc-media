Пользователь Claude [рассказал](https://x.com/Florious95/status/2118340225177124908), как ему удалось избежать KYC после перехода на тариф Ultra. С 25 октября он пользуется подпиской и утверждает, что за всё это время сервис ни разу не потребовал подтвердить личность.

По его словам, в сообществе принято считать, что переход на Ultra практически гарантирует проверку документов, причём даже для пользователей из США. Однако у него в статусе KYC до сих пор указано "Not Required".

Весь способ сводится к одной идее: заблокировать на компьютере все домены Claude и Anthropic, оставив единственный контролируемый канал подключения.

Для этого он прописал десятки доменов в hosts с перенаправлением на localhost, подключил VPS через Tailscale и поднял на сервере обычный HTTP-прокси.

Затем настроил Claude Code через официальный механизм корпоративного прокси, отключил телеметрию и отправку отчётов об ошибках. Для веб-версии используется отдельный экземпляр Chrome с тем же прокси.

В результате все подключения и DNS-запросы проходят через один VPS, а внешний IP-адрес не меняется при переключении между клиентами.

Он также поделился списком доменов, которые необходимо заблокировать через hosts.

Для каждого домена нужно добавить две записи: одну для IPv4, другую для IPv6. Обе должны указывать на локальный адрес.

Блокируются следующие домены и их поддомены:

- anthropic.com: www, api, console, auth, oauth, a-api, a-cdn, api-staging, statsig, mcp-proxy, mcp-proxy-staging, docs, support, status, portal, api-pr-preview.
- claude.ai: www, api, assets, preview, downloads.
- claude.com: www, api, code, platform, releases, docs, status, support, mcp, а также gcal.mcp, gmail.mcp, slack.mcp и microsoft365.mcp.

Для настройки Claude Code через прокси автор рекомендует использовать [официальную инструкцию Anthropic.](https://code.claude.com/docs/en/corporate-proxy)

Второй шаг: настройка прокси в Claude Code через settings.json.

В разделе `env` необходимо указать переменные `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY` в верхнем и нижнем регистрах, а также `CLAUDE_CODE_HTTP_PROXY`, `CLAUDE_CODE_HTTPS_PROXY` и `grpc_proxy`.

Во всех случаях используется внутренний Tailscale-адрес VPS с указанием порта и протокола `http`. Даже для `HTTPS_PROXY` нужно указывать `http`, поскольку HTTPS-запросы передаются через туннель CONNECT.

В `NO_PROXY` и `no_proxy` следует оставить только локальный loopback-адрес и `localhost`.

Отдельное внимание разраб уделил предотвращению утечки реального IP-адреса.

По его словам, после декомпиляции Claude Code 2.1.309 выяснилось, что некоторые каналы отправки данных потенциально могут раскрывать настоящий IP.

Поэтому он рекомендует установить значение `1` для следующих переменных:

- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`
- `DISABLE_TELEMETRY`
- `DISABLE_ERROR_REPORTING`
- `DISABLE_GROWTHBOOK`
- `DO_NOT_TRACK`

Таким образом разраб пытается направить весь трафик Claude Code через один VPS и исключить прямые подключения. При этом сама настройка не гарантирует отсутствия утечек IP или проверок KYC.
