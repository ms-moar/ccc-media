Что решает rulesync 43.8.0

Это генератор: из одного дерева-источника он пишет родные файлы каждого рантайма. Факты — из README (https://github.com/dyoshikawa/rulesync) и cli-commands.md (https://github.com/dyoshikawa/rulesync/blob/main/docs/reference/cli-commands.md), версия 43.8.0 от 2026-11-08.

- Один источник на всех. Правила, скиллы, хуки, MCP, команды и сабагенты лежат в одном дереве. Флаг --input-roots берёт его вне проекта (пример из доки: ~/.aiglobal/.rulesync), то есть ровно наш нейтральный корень.
- Рантаймы. В матрице README у Claude Code, Codex CLI, Hermes Agent, Grok CLI и Pi Coding Agent отмечены скиллы и хуки — это все пять наших.
- Обычные файлы, а не симлинки. Генератор пишет каждому рантайму в его формате; из доки: «the writer only ever creates real files». Значит, Hermes не сможет через skill_manage переписать канон, как мог бы через симлинк.
- Проверка дрейфа без хука на старте. rulesync generate --check сверяет записанное с источником, выходит с кодом 1 и ничего не пишет.
- Пин. Внешние источники фиксируются в rulesync.lock; install --frozen падает, если lock расходится, а install --outdated сообщает об отставании, ничего не меняя.
- Откат. Вернуть дерево источника и rulesync.lock к нужному коммиту и снова запустить generate. Цели, которые больше не генерируются, снимает generate --retire-targets.
