# Claude Code: логика Tasks после v2.1.233

Факт из CHANGELOG (v2.1.233):

> Todo/task-tracking tools (TaskCreate/Get/Update/List, TodoWrite) are no longer available on Opus 4.8, Sonnet 5, Fable 5, Mythos 5, and newer models; set CLAUDE_CODE_ENABLE_TODO_TOOLS=1 to bring them back

## Что это значит

Не «убрали из продукта», а **сняли с новых моделей по умолчанию**: env-флаг возвращает, на старых моделях тулы живы, хуки TaskCreated`/`TaskCompleted остались для opt-in-случая.

Официальной причины changelog не даёт — вывод из наблюдаемого: новым моделям bookkeeping-скретчпад больше мешал, чем помогал — расход токенов и ходов на ведение списка вместо работы, интерлив todo-апдейтов ломал вывод (фикс — прямо в 2.1.234), а «+7% prompt tokens» в той же 2.1.233 показывает, куда сместился бюджет: в системные инструкции о доведении работы.

## Текущая логика надёжного последовательного выполнения

Обязанности разошлись по слоям вместо одного тула:

- **Секвенирование** — сама модель: харнесс-инструкция «finish the whole task, report completion only when fully done; частичный скоуп — явно назвать, что не сделано». Контракт результата вместо чек-листа в тулзе.
- **Согласование до старта** — plan mode (`EnterPlanMode` / `ExitPlanMode`).
- **Параллельное и фоновое** — Agent tool + task-notifications (`TaskOutput` / TaskStop — это фоновые задачи-агенты, другой «Task», он жив).
- **Детерминированная оркестровка** — Workflow (pipeline / phases): порядок держит скрипт, не память модели.
- **Циклы** — /loop + ScheduleWakeup.
- **Выживание длинных задач** — авто-суммаризация контекста («work continues — не сворачивайся раньше») вместо переноса todo-списка через компакт.
